# Bijective Transformation Guide

## Overview

TInCuP now supports **bidirectional transformation** between C++ `custom` function declarations and CPO+tag_invoke code. This feature enables:

1. **Forward transformation**: `custom` → CPO (for C++20 compatibility today)
2. **Reverse transformation**: CPO → `custom` (for C++29 migration) - Coming soon
3. **Round-trip validation**: Proof of semantic equivalence

This is part of our support for the C++29 `custom` keyword proposal, demonstrating that `custom` is **mathematically equivalent** to the tag_invoke pattern.

## Quick Start

### Installation

```bash
# Basic TInCuP (includes forward transformation)
pip install TInCuP

# With reverse transformation support (coming soon)
pip install TInCuP[reverse]
```

### Basic Usage

```bash
# Transform custom declarations to CPO code
cpo-bidirectional from-custom my_lib.hpp -o my_lib_cpo.hpp

# Parse and preview (dry run)
cpo-bidirectional from-custom my_lib.hpp --dry-run

# See what was parsed
cpo-bidirectional parse my_lib.hpp
```

## Forward Transformation: custom → CPO

### Example Input

```cpp
// my_lib.hpp
#pragma once

namespace mylib {

// Simple function
custom void print_hello();

// Template function
template<typename T>
custom void serialize(const T& obj, std::ostream& os);

// Noexcept function
custom int compute_hash(const std::string& str) noexcept;

} // namespace mylib
```

### Transform to CPO

```bash
cpo-bidirectional from-custom my_lib.hpp -o my_lib_cpo.hpp
```

### Generated Output


## Command Reference

### `from-custom` - Transform to CPO

```bash
cpo-bidirectional from-custom INPUT [-o OUTPUT] [OPTIONS]

Options:
  -o, --output PATH     Output file (default: stdout)
  --no-metadata         Disable bijective metadata
  --dry-run            Parse only, don't generate
  --verbose, -v        Verbose output
```

**Examples:**

```bash
# Basic transformation
cpo-bidirectional from-custom src/api.hpp -o include/api_cpo.hpp

# Preview what will be generated
cpo-bidirectional from-custom src/api.hpp --dry-run

# Generate without metadata (smaller output)
cpo-bidirectional from-custom src/api.hpp --no-metadata
```

### `parse` - Inspect Parsed Functions

```bash
cpo-bidirectional parse INPUT [--json]

Options:
  --json    Output as JSON
```

**Examples:**

```bash
# Human-readable output
cpo-bidirectional parse src/api.hpp

# JSON output (for tooling)
cpo-bidirectional parse src/api.hpp --json > parsed.json
```

### `to-custom` - Reverse Transform (Coming Soon)

```bash
# Future functionality
cpo-bidirectional to-custom cpo_file.hpp -o recovered.hpp
```

Requires: `pip install TInCuP[reverse]`

### `validate` - Round-trip Validation (Coming Soon)

## Supported C++ Features

### ✅ Fully Supported

- Simple functions: `custom void foo();`
- Template functions: `template<typename T> custom T bar(T x);`
- Multiple template parameters
- Noexcept specifications
- Complex parameter types (references, pointers, templates)
- Namespace declarations
- Inline function bodies

### 🔄 Partially Supported

- Variadic templates (basic support)
- Concepts in requires clauses (preserved in template params)

### ❌ Not Yet Supported

- Member functions (per `custom` keyword restrictions)
- Constructor/destructor customization
- Default parameter values (stripped during transformation)

## Metadata for Bijective Transformation

By default, generated CPO code includes metadata comments enabling reverse transformation:

```cpp
// TINCUP_GENERATED_FROM_CUSTOM
// TINCUP_ORIGINAL_SIGNATURE: template<typename T> custom void serialize(const T&);
// TINCUP_FUNCTION_NAME: serialize
// TINCUP_TEMPLATE_PARAMS: typename T
```

This metadata allows:
- Reverse transformation (CPO → custom)
- Round-trip validation
- Proof that transformation is lossless

To disable metadata:

```bash
cpo-bidirectional from-custom input.hpp --no-metadata
```

## Parser Limitations

The regex-based parser handles most common C++ patterns but has limitations:

### ✓ Handles Well

```cpp
template<typename T, typename U>
custom void foo(const T& x, U&& y) noexcept;

custom auto bar() -> std::pair<int, double>;

namespace ns::nested {
  custom void baz();
}
```

### ⚠️ May Struggle With

```cpp
// Extremely nested templates
custom void complex(std::map<std::string, std::vector<Foo<T>>>& x);

// Preprocessor macros in signatures
custom void macro_heavy(MACRO_TYPE x);

// Attributes before custom
[[nodiscard]] custom int get_value();
```

**Solution**: For complex cases, simplify the signature or use a workaround.

## Troubleshooting

### Issue: "No custom functions found"

**Cause**: Parser didn't detect any `custom` keyword

**Solutions**:
1. Verify `custom` keyword is present
2. Check function declaration syntax
3. Use `--dry-run` to see what parser found

### Issue: Generated code doesn't compile

**Cause**: Complex template syntax not handled correctly

**Solutions**:
1. Simplify function signature
2. Report issue: https://github.com/sandialabs/TInCuP/issues
3. Manually adjust generated code

### Issue: Missing template parameters

**Cause**: Parser didn't detect template syntax

**Solution**: Ensure `template<...>` is on line immediately before `custom`

## FAQ

**Q: Do I need the modified clang to use this?**

A: No! The transformer uses regex parsing - no compiler needed. You only need modified clang if you want to actually *compile* code with the `custom` keyword.

**Q: Is the transformation lossless?**

A: With metadata enabled (default), yes. The transformation preserves all information needed for reverse transformation.

**Q: Can I use this in production?**

A: The forward transformer (custom → CPO) is production-ready. Reverse transformation is coming soon.

**Q: How does this compare to manual CPO writing?**

A: It's exactly what TInCuP generates - identical output. This tool just adds the ability to start from `custom` declarations.
